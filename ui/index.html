      准备添加网站
      Cloudflare 账户与域名
      域名需要已接入 Cloudflare，并显示 Active。
      打开 Cloudflare 账户 ↗ · 官方获取说明 ↗
      选择你的账户 → 按 Ctrl + K → 搜索 Copy account ID 并复制。也可进入域名概览，在页面底部 API 区域复制 Account ID。Google 登录不影响此 ID，它不是邮箱。
      打开 Cloudflare 域名列表 ↗ · 官方获取说明 ↗
      选择要使用的域名 → Overview（概览）→ 页面底部 API 区域 → 复制 Zone ID。确保该域名属于上面填写的账户。
      查看 Cloudflare 域名 ↗
      填写列表中状态为 Active 的域名，如 example.com；不带 https:// 或路径。新增网站使用这个域名下的子域名。
      优先使用系统 PATH 或项目 bin；找不到时从 Cloudflare 官方下载，校验后自动填写并保存路径。
      自动配置 API Token
      提供 API Tokens Write 授权，分别管理写入和只读令牌，也可修复已保存令牌的缺失权限。
      打开 Cloudflare 创建授权令牌 ↗
      API Tokens → Create Token → Create Additional Tokens 模板 → 创建并复制令牌。该模板提供 API Tokens Write；普通 DNS / Tunnel 令牌不能代替。
      授权令牌可管理用户 API 令牌。新令牌限定为当前账户和域名。修复当前令牌会新增本平台所需权限，保留原有权限、有效期和 IP 限制；仅支持当前保存且可验证的用户令牌。
      写入令牌
      Tunnel、DNS、Zone，以及勾选的 Turnstile 权限。
      只读令牌
      仅 Tunnel Read、DNS Read 和 Zone Read；新建时自动加密保存，写入令牌不受影响。
      未勾选记住时，授权令牌仅用于本次操作。创建的业务令牌自动加密保存，不回显到页面；创建新令牌会替换本机使用的凭据，旧令牌保留在 Cloudflare；修复当前令牌保留其原值，新增权限后请重试此前失败的操作。
      本机凭据保险库
      输入后加密保存；留空保留已有凭据。
      创建只读 Token ↗
      可选：选择账户 Tunnel Read、区域 Zone Read 和 DNS Read；资源限定到同一账户和域名。
      ✓ 写入 API Token 已加密保存
      当前凭据已配置，无需重复填写。为保护令牌，不显示原文。
      已保存表示本机存储完成；云端权限将在实际操作时核验。

      打开令牌创建向导 ↗
      先保存 Account ID 和 Zone ID，即可打开限定到当前账户与域名的预填创建页。
      前往创建 API Token ↗ · 官方创建教程 ↗
      My Profile → API Tokens → Create Token → Create Custom Token。创建后复制完整令牌，粘贴到上方，再点击“加密保存凭据”。令牌只展示一次；这里填写 API Token，不是 Global API Key。
      创建 Tunnel 必需：账户 → Cloudflare Tunnel → 编辑，账户资源选择当前账户。下方预填链接只填写 DNS 和 Zone 权限，请补充 Tunnel 权限后再创建令牌。
      LanBridge 所需权限与范围
      • 账户：Cloudflare Tunnel — Edit（或 Cloudflare One Connector: cloudflared — Write）。
      • 区域：DNS — Edit；Zone — Read。
      • 自动创建人类验证：账户 Turnstile — Edit。
      • Account Resources 仅选择你的账户；Zone Resources 仅选择当前域名。
      Continue to summary → 检查权限 → Create Token。权限显示名称可能随 Cloudflare 界面调整。
      新标签页打开 Cloudflare；完成确认后回到这里继续。此向导不会自动生成或读取令牌。
      

      粘贴后点击下方“加密保存凭据”。保存失败时保留输入，可以修正后重试。

      日常配置直接使用管理台；脚本用 CLI / API，AI 工具用 MCP，AI 操作流程用 SKILL。四种入口使用同一套配置与访问策略。
      

      

      命令行
      CLI · 在终端执行任务
      适合本机检查、批处理和独立脚本。先在 PowerShell 进入 LanBridge 项目目录。
      .\.venv\Scripts\python.exe run.py capabilities
.\.venv\Scripts\python.exe run.py status
.\.venv\Scripts\python.exe run.py ensure-connector
      capabilities 列出支持的命令；status 查看配置；ensure-connector 检测或安装连接器。
      管理台运行时，capabilities / status 可直接使用。CLI 修改操作需先停止平台，或改用 API / MCP。配置令牌使用 configure-secret 的隐藏输入。
      

      程序接口
      API · 集成自己的程序
      适合自动化脚本或其他本机程序。平台需要保持运行，管理接口默认 http://127.0.0.1:8890/api/。
      • POST /api/login：管理员登录，获得会话 Cookie 和 csrf。
      • GET /api/state：查看网站、缺少的配置和连接器状态。
      • POST /api/sites：保存网站与访问策略。
      • POST /api/connector/ensure：检测 / 下载连接器。
      • POST /api/cloudflare/preview → apply：预览，再提交 revision 发布。
      Python 示例：登录并读取状态
      import getpass
import httpx

base = "http://127.0.0.1:8890"
with httpx.Client(base_url=base, headers={"Origin": base}) as client:
    login = client.post("/api/login", json={
        "username": input("管理员用户名："),
        "password": getpass.getpass("管理员密码：")
    })
    login.raise_for_status()
    client.headers["X-CSRF-Token"] = login.json()["csrf"]
    state = client.get("/api/state")
    state.raise_for_status()
    print(state.json()["cloudflare_setup"])
      所有 POST 需带 Origin；登录后的 POST 还需会话 Cookie 和 X-CSRF-Token。管理员接口只接受本机连接。
      

      AI 工具接口
      MCP · 让 AI 调用平台工具
      在支持 stdio MCP 的客户端添加 LanBridge 桥接器。平台需先启动，桥接器通过本机 API 登录操作。
      {
  "mcpServers": {
    "lanbridge": {
      "command": "<项目目录>/.venv/Scripts/python.exe",
      "args": ["<项目目录>/mcp_server.py"]
    }
  }
}
      将项目目录替换成实际绝对路径；不同客户端的配置入口可能不同。
      • 通过客户端安全环境配置提供 LANBRIDGE_ADMIN_USERNAME 和 LANBRIDGE_ADMIN_PASSWORD，不把真实密码写进项目文件。
      • 可选 LANBRIDGE_ADMIN_URL 指定本机管理地址；默认端口 8890。
      • 常用工具：lanbridge_status、lanbridge_save_site、lanbridge_prepare_connector、lanbridge_preview、lanbridge_apply。
      连接后让客户端列出工具。发布需要 preview 返回的 revision；令牌和新建访客口令请在管理台填写。
      

      AI 操作说明
      SKILL · 让 AI 按正确流程操作
      SKILL 告诉 AI 如何使用 CLI、API 或 MCP，包括配置检查、先预览再发布、失败后的核对流程。
      1. 找到项目内的 skills/lanbridge/SKILL.md。
      2. 将整个 lanbridge 技能文件夹安装到你的 AI 客户端支持的技能目录。
      3. 重新加载技能，然后要求 AI“使用 lanbridge 技能检查配置并管理网站”。
      Codex 的个人技能目录通常为 %USERPROFILE%/.codex/skills；也可先让 AI 直接读取项目里的 SKILL.md。当前项目已包含技能文件，是否启用取决于客户端安装。
      SKILL 提供操作指引；执行仍通过 CLI、API 或 MCP。它不自动授予凭据或配置客户端。

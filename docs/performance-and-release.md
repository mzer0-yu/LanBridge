# 性能测量与本地打包

## 隔离测量

在项目根目录运行，输出目录必须是 `.test-artifacts/` 下尚不存在的子目录：

```powershell
.\.venv\Scripts\python.exe scripts/benchmark.py --output-dir .test-artifacts/performance-new
```

工具只创建自己的测试数据、随机空闲回环端口和模拟源站，不读取正式 `data/`，不配置 Cloudflare，不打开浏览器。结束时正常关闭自己创建的实例；启动失败时仅清理自己创建的子进程。测试数据含随机测试管理员凭据，按运行数据处理，不公开分享；公开报告只含指标。

三个独立实例分别配置 1、10、100 个网站。每组记录一次管理台就绪时间、30 次热状态请求、8 并发共 160 次 32 KiB HTTP 转发，以及同量模拟源站直接请求对照。Windows 内存/CPU 使用真正拥有两个测试监听端口的后端 PID，避免误测虚拟环境的启动包装进程。报告保存为 `report.json`。

2026-10-07 本机短时样本：

| 网站数 | 就绪时间 | 状态接口中位 / P95 | 转发中位 / P95 | 负载后工作集 |
| --- | --- | --- | --- | --- |
| 1 | 566 ms | 1.96 / 2.67 ms | 18.94 / 54.31 ms | 66.77 MiB |
| 10 | 565 ms | 1.55 / 2.31 ms | 19.09 / 55.31 ms | 66.59 MiB |
| 100 | 543 ms | 3.80 / 4.98 ms | 21.11 / 50.37 ms | 67.15 MiB |

对应源站直接请求中位约 16–17 ms；转发约 341–371 请求/秒。该数字包含模拟源站、Python 测量客户端与本机调度成本，不是公网吞吐上限、长期压力验收或优化前后对比。尚未据此修改业务核心缓存或并发机制。

启动器检测 CLI 的 5 次本机样本为 207.93–222.50 ms，中位 213.41 ms。启动器原先同步等待这个进程；现在异步读取结果，现有状态行显示检测中，检测期间禁用重复操作。15 秒超时、失败、窗口关闭均回收本次检测辅助进程；不关闭服务实例。启动、打开、关闭/重启操作仍在检测后核验目标身份，不因异步而跳过检查。隔离延迟 CLI 验证界面定时器持续运行。

## 生成源码包

```powershell
.\.venv\Scripts\python.exe scripts/build_release.py
# 上一次产物已存在时，指定新的输出目录：
.\.venv\Scripts\python.exe scripts/build_release.py --output-dir .test-artifacts/release-new
```

默认输出 `.test-artifacts/release/`：源码 ZIP、`manifest.json`、`SHA256SUMS.txt`。版本取自根目录 `VERSION`。包是当前本地工作树快照，包含符合规则的未提交/未跟踪源码，不能冒充远端某个提交。

Git 文件清单与明确的目录、扩展名和根入口白名单共同决定内容。发现不认识的候选文件、隐藏文件、符号链接、越界路径或缺失必要入口时拒绝打包。正式配置、保险库、数据库、连接器、虚拟环境、测试产物、Git 元数据均不进入源码包。白名单不是内容秘密扫描；发布前仍须审阅源码中的凭据、域名与个人信息。

清单包含每个源码文件的大小与 SHA-256，并同时放入 ZIP。生成后核查 ZIP CRC、逐文件内容和校验文件。相同源码及版本产生相同 ZIP；已有产物不覆盖，选择新目录生成。打包脚本不安装依赖、不提交、不推送、不创建远端 Release。用户确认后才进行单独的 GitHub 发布操作。

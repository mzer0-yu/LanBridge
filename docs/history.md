## 2026-10-07 · 初始化竞争遗漏入口补查

来源：review-status.md。

上轮 R25 只覆盖 vault.key，不应据此声称整个初始化流程已经无误。本轮追踪旧数据库升级和服务默认值初始化，确认两处同类遗漏入口；归并计数保持 25 类，不再把两个触发入口算作两个新的安全漏洞类别。

- 两个初始化器都读取到 sessions 缺少 access_token_id，随后分别 ALTER TABLE，旧实现受控线程交错复现 duplicate column name，导致一个入口启动失败。现在升级前执行 BEGIN IMMEDIATE，在同一 SQLite 写事务内检查和添加各列；失败整体回滚并关闭数据库连接。另验证中途失败后没有半升级列，重试成功且原凭据仍可解密。

## 2026-10-07 · 异步反馈遗漏入口复查

来源：review-status.md。

本轮确认并补齐三处遗漏：日志设置/网关端口保存后的刷新反馈、登录批准结果跨请求回写，以及其他只读 API 的超时。属于已记录 R19/R20 的遗漏入口，不将 9 个新增测试或多个接口重复算作新缺陷类别，历史归并仍为 23 类。此前这些机制尚未覆盖所有入口，不能将前轮通过称为完整解决。

- 日志大小和网关端口保存成功后，状态读取失败原先会覆盖“已保存”为错误；现在先保留保存结果，再原位提示“页面刷新失败，请点击顶部刷新重试”。不增加冒泡提示。退出/切换会话后的旧结果不清除新表单修改，也不覆盖新反馈。

## 2026-10-07 · 登录与转发输入边界补查

来源：review-status.md。

本轮检查本机批准登录、临时授权鉴权、异常输入和访问验证恢复。修复 F9/F10/F11；没有发现或声称认证绕过、密码泄露、任意执行等已被证明的漏洞。

确认码错误返回 400，保留 pending 状态；正确代码随后仍能批准并领取会话。比较前转换成原有字符串形式，再检查六位 ASCII 数字，保留此前数字输入的兼容行为。验证码不会因为格式错误被消费，也没有放宽浏览器绑定、Origin 或 CSRF 保护。

Content-Length 先去除前导零，限制有效位数和数值，避免 5000 位数字触发整数转换异常。异常输入在地址解析/上游连接前返回 413，验证入口使用相同转换限制。正常 0 字节与 5 字节上传验证规范化后的上游长度头和内容。复现来自隔离 ASGI 请求，不将其等同于已验证真实公网 HTTP 解析器可利用的漏洞。

JSON 额外加固：管理员请求解码的 RecursionError 转为统一格式错误；验证服务响应解码异常返回 503 且不签发 Cookie。当前运行时能解析 1100 层 JSON，不能据测试原型的错误预期判定漏洞；3000 层请求在网关会先被既有 4 KiB 限制拒绝，管理员 20 KiB 请求范围内的解码异常则受格式错误处理。网关原本的大小保护有效，没有新记一项网关深层 JSON 绕过。

访问验证页 30 秒超时后在原位显示“验证请求超时，请重试。”，恢复按钮和验证组件；重新取得令牌后可成功提交。没有增加冒泡提示或改动布局样式。

证据：[test_input_boundaries.py](../tests/test_input_boundaries.py) 新增 11 个 Python 场景；[test_gate.js](../tests/test_gate.js) 增加卡住、超时、重试恢复流程。原实现中确认码 TypeError、普通转发长度转换异常，以及前端缺少 deadline 均有复现。其余场景用于证明保护、内容保真和兼容行为，没有把所有新增测试算成新增缺陷。

## 鉴权边界

来源：security-review.md。

现有代码及回归检查没有发现直接绕过真人验证、访客口令或管理员登录的路径。Cookie 签名绑定网站、域名、IP、策略版本和有效期；Turnstile 服务端检查 success、hostname 和 action。管理员监听 loopback，检查 Host、Origin、会话和修改请求的 CSRF。

普通网站源站 DNS 在连接前校验并固定局域网 IP，禁止公网、链路本地地址与本平台端口。HTTP 重定向不由代理自动追随；客户端不能指定任意源站。客户端转发头被清理，HTTPS 保持证书校验。只有 loopback 连接的 Cloudflare 访客头被信任。

本机其他进程与当前 Windows 用户属于信任边界：能连接网关的本机进程可以伪造 Cloudflare 访客头；拥有当前用户权限的恶意程序也能访问该用户的凭据。不要把网关改为监听公网，不能把 IP/国家限制视为对本机恶意程序的防护。

## 尚存的运行限制

来源：security-review.md。

- 有限的并发配额仍可被占满；这是资源止损而非可用性保证。长期 WebSocket/SSE 会占用名额。WebSocket 已限制消息和字节速率，但没有每日字节配额；同一 IP 可建立多条连接，源站仍应限制昂贵业务操作。
- 暂存预算不替代磁盘剩余空间检查；操作系统磁盘不足会导致请求失败并清理暂存。转发和 Uvicorn 运行错误日志已分别轮转（各约 20 MiB），外部启动器捕获的 stdout/stderr 和 CLI 输出仍应设置部署侧保留期限。
- 每请求仍读取本机配置/凭据，数据库与加解密开销尚未单独压测。依赖漏洞扫描、Cloudflare 账户实际 WAF/限流规则核验和多机压力测试不在本次完成范围。
- Turnstile 证明一次验证通过，不等于持续防机器人；验证会话中的访客仍可能滥用源站。不能承诺已“彻底防住 DDoS”。

Cloudflare 的边缘 DDoS 防护承担公网攻击流量过滤，本机限额保护已经进入网关的请求。可核对 [Cloudflare DDoS 防护说明](https://developers.cloudflare.com/ddos-protection/about/) 和 [HTTPX 连接复用说明](https://www.python-httpx.org/async/)。

### 显式远程管理入口

LanBridge 自身入口通过 `target=lanbridge` 显式开启，经过网关的 HTTPS、访问策略和资源限制后进程内分发。远程管理实例只允许启用且未暂停的自身入口主机名，不改变本机管理监听器的 Host/loopback 校验。原普通代理的自身端口阻断继续保留。

远程禁止账户首次初始化、本机登录授权所有接口、Cloudflare 浏览器授权及平台退出；管理操作继续要求管理员会话、同源 HTTPS Origin 和 CSRF。Cookie 仅属当前主机并有 Secure/HttpOnly/SameSite=Strict；远程密码检查移至工作线程，登录按来源及总量限速，管理 JSON 请求读取限制为 20 KB。远程 `/client` 按入口策略开放且包含配置的局域网地址，部署者应据此选择访问策略。

## EncoderPLL 响应完整性

来源：validation.md。

旧生产日志没有路径或请求 ID，不能将历史 h11 异常逐条关联到共享 JSON，也不能证明历史源站为何提前断流。隔离的真实 TCP/Uvicorn 测试中，源站声明 5,307,218 字节、只发送 1,048,576 字节后断开：旧 BaseHTTPMiddleware 响应中继复现了 `Too little data for declared Content-Length`，掩盖上游断流异常。修复使用纯 ASGI 访问检查、明确的响应资源生命周期，并在发送已声明长度的响应前核验完整原始字节；该场景现在返回完整 502，关联日志记录 RemoteProtocolError 与实际读取量。

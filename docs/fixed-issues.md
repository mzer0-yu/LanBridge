# LanBridge 已修复问题清单

## 2026-10-09：配置操作迟到结果与重新登录提示

退出登录或重新登录后，部分操作虽然由统一请求层拒绝旧结果，外层回调仍会显示旧错误、清空当前输入、关闭新表单，或继续发起后续写请求。授权、隧道、账户/凭据/网站/密码保存、验证配置、域名、令牌管理、连接器维护和发布流程补充回调会话检查；验证及发布的分步操作在下一次写入前也检查会话。新增回归在成功和失败两种迟到结果下核对新会话反馈、输入及后续请求数量，见 `tests/test_navigation.js`。

隧道令牌缺失时的自动展开状态原先保留在 DOM 中，重新登录后同样缺失状态可能不再触发展开。退出登录清除该展示状态，新会话重新判断；回归见 `tests/ui/auto-tunnel-setup-check.js`。这些修复不撤销旧请求已完成的服务端变更。

## 2026-10-08：访问验证异常响应与恢复流程

验证 API 原有空 408/413 响应，以及限流、繁忙和策略拒绝的纯文本响应，与页面直接调用 `response.json()` 的假设不一致。前端解析异常会直接暴露给访客。验证端点各拒绝入口现统一返回禁止缓存的 JSON，前端兼容边缘代理返回空白、HTML、截断响应，并要求成功响应明确含 `verified: true`。

失败后清除验证结果，未取得新结果时不再提交；首次成功验证仍自动进入网站，提交失败后的恢复由访客点击重试，避免组件重置后形成自动请求循环。补充组件错误、超时、脚本加载失败提示，使用可取消计时器兼容缺少 `AbortSignal.timeout` 的浏览器。保留人类验证、口令、Origin、限流、主机/IP/策略绑定检查。

## 加固与效率改善：不计入上述 25 类

- TokenManager.provision 内部方法补齐 authority/remember/human_check 类型校验；管理 HTTP 入口原本已校验，CLI 提供固定类型，因此不计为新的可达 API 缺陷。

- 验证正文流式限量及接收期限、管理日志设置正文限量；属于资源与输入边界加固。
- HTTP/WebSocket/验证的全局及 IP 并发额度、进入速率限制，响应发送完成后释放额度。
- 下载暂存单个/总量限制和接收期限，避免无界磁盘占用。
- 身份限流由增长队列改固定空间计数，容量满时拒绝新身份而不驱逐仍有效的限额。
- scrypt 校验放入线程，并限制并发；上游连接建立取消、暂存写入/关闭之间补齐清理保障。
- WebSocket Origin 校验、队列与发送期限；增加消息/字节预算。
- 日志导出临时文件放入受保护 data 目录；JSON 解码深度异常统一安全失败。没有证明原系统 TEMP 或深层 JSON 已构成可利用的攻击。
- 日志追加未超限时跳过全历史扫描；降低上限仍立即剪裁。
- 日志导出逐条生成受限内存快照并分块发送，响应结束/断开关闭临时文件。
- 临时令牌最近访问时间限频写入，鉴权/过期/撤销继续逐请求检查。
- 固定私网对象只构造一次；复用隔离的上游连接。
- 临时权限读取状态时跳过日志内容和容量查询；去除日志容量元数据。

这些是实际改动，但不统一包装成已发生故障。数值上限与部署限制见 README；整体吞吐没有经过满载基准证明。

## 我在改动或验证中犯过的错误：单独披露

- 新增公网转发列表开关时，网关禁用响应遗漏 Content-Type，导致浏览器中文乱码。这是我在新功能中引入的问题；用户报告后补齐 text/plain; charset=utf-8，相关 15 项回归通过，实际公网 /client 返回 404 且中文 UTF-8 内容核验通过。不能包装成发现原有漏洞。

- 访问时间限频改造曾出现登录/访问时间顺序兼容问题，完整回归发现并修正。不能把它算作新的原有缺陷。
- 确认码改造的中间版本使用严格字符串校验，会改变既有数字输入行为；在加载前恢复兼容，并补充数字输入回归。
- 深层 JSON 测试最初错误假定 1100 层一定触发当前 Python 的解码递归异常。核对实际运行时后更正用例；原网关 4 KiB 正文限制一直有效。测试预期错误不算产品 bug。
- 个别测试缺失父目录或验证密钥、维护脚本缺少启动请求正文、浏览器截图未等动画结束，也属于验证/维护错误，不算产品缺陷。

因此不能回答“所有问题都和我无关”。已修复清单中的代码缺陷、开发过程引入的回归，以及测试工具错误需要分别承担责任。此前把“本轮检查完成”说得像“所有问题彻底解决”，并将 11 类描述为累计，确实不准确。

# 更新与自动重载

LanBridge 将源码更新检测、重载协调和服务生命周期分开管理。默认启用受控自动重载，允许短暂中断：每秒检查源码内容，连续稳定至少 8 秒后校验 Python 语法和新解释器的启动模块导入，再退出旧实例并启动新解释器。不是在运行中的模块上使用 importlib.reload。

更新协调器只观察项目 `run.py`、`lanbridge/*.py` 和 `ui/` 顶层静态文件；不观察 data、bin、依赖、测试或文档。修改时间变化但内容未变化不会触发重载。运行目录、已保存配置和登录会话仍使用原数据目录；连接器恢复更新前的启停状态，不自动打开浏览器。网关、管理台和连接器会短暂中断。

浏览器授权进行中、管理写操作或域名迁移持有锁时，延后重载；可恢复的 DNS 跟踪任务由新实例重新加载。界面展示等待、校验失败或自动重载状态。前端文件变动只提示刷新页面，不重启后端。前端刷新可能清空尚未保存的表单，因此不强制刷新。

CLI：默认 `.venv\Scripts\python.exe run.py serve` 启用检测；`serve --no-hot-reload` 关闭自动执行，后端更新时显示“更新待生效，请重启实例”。显式重启保留这个选择。自动重载沿用现有重启机制，应用待生效端口，并保留管理端口冲突时回退到旧端口的机制。

首次升级仍需重启一次旧实例，它没有新协调器，不能监测更新。之后在原目录修改源码会自动执行上述流程。不要在生产目录逐个写入大型版本；先准备完整更新，再统一替换，避免稳定间隔内出现语法正确但不完整的代码集合。

校验失败保持旧实例运行，修正源码后重新检测。语法与导入校验不等于所有业务逻辑正确；新版本启动或运行时失败尚不支持自动回滚源码，也不自动安装新依赖。新增依赖、数据迁移、包结构调整仍需要人工核对。当前方案不承诺转发长连接不中断。
